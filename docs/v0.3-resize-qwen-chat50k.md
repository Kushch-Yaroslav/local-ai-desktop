## Confirmed contracts and fixes

### Native browser geometry

The existing presentation transform remains authoritative. A compact 24-DIP bottom-right grip uses the trusted native input shield, outside the project DOM. During user-owned dragging, measured screen movement is converted through Page Zoom and Presentation Scale to CSS dimensions. Dragging selects Custom size, retains URL/Page/session/zoom/scale and persists the custom workspace in SQLite on release. Presets still reset to their configured dimensions. Auto Fit retains its fitting semantics; numeric scale retains its value. Existing pan and viewport area/dimension limits remain enforced. Agent ownership expands the input shield, removes grip styling and blocks user resizing.

Two reproducible full-width selection failure paths existed: coordinates could exceed the CSS viewport and be rejected by grounding; a cancelled native pointer sequence discarded an otherwise valid drag. The overlay now clamps points and commits the last valid bounded rectangle on pointer cancellation/capture loss. Grounding clamps again and rejects empty intersections. Escape still cancels. The historical physical event was not recorded, so these reproduced code paths are not asserted to explain every historical edge selection failure.

### Runtime tools and criteria

* A valid `run_terminal task_action=start` fell through the permissions matcher to a denial. The valid start branch now reaches the existing command/root permission checks. Task limits and approvals are unchanged.
* The selector-hint generator produced `#expert > ` for nested duplicate IDs and an empty descendant path. It now requires a nonempty path; candidates remain checked for uniqueness. A bounded semantic DOM outline includes empty containers and safe real selectors.
* Ordinary approved-page `read`/`inspect` is diagnostic and does not require formal Region verification scope. Explicit scopes, QA, captures, original-region evidence and supplementary criteria retain URL/viewport/project protections. Diagnostic CSS observation is not passing criterion evidence.
* `deliverables` retains its existing public API: top-level **`id`** identifies a deliverable; **`criteria[n].id`** identifies a criterion. `scenario_refs` uses **`deliverable_id` / `criterion_id`**. Registration selects an existing ID and never silently creates or chooses a parent. Missing/unknown parent diagnostics identify `$.id`, give task-local existing IDs, and prohibit identical retries. Nested omissions name paths such as `$.criteria[0].id`. The schema now exposes the existing text length bound and explains the parent argument. Failed calls do not mutate metadata or manufacture evidence. Registered criteria remain immutable.
* The real control found `scenario_refs` rejecting its own saved scenario when the model included legal `id`/`goal` labels. The runtime removed these metadata fields from the execution side only. Both sides now use the same projection; target, viewport, preconditions, required state, steps, assertion and timeout remain equal. Positive and per-field negative regressions cover this fix.
* Standard Vite CSS-module sourcemaps were embedded in the JSON string passed to `updateStyle`; the old recognizer looked only at the end of the JavaScript module. The bounded parser now reads that specific literal transport without executing code, requires exact original source bytes, and rejects stale or detached maps. The Vite fixture enables CSS dev sourcemaps. Without suitable source binding, the conservative Gate review remains correct.
* Missing-parent metadata failures now have the same bounded 3/4 warning/stop pattern as existing malformed criterion protection, surviving Continue. No retry limit was increased.

### Continue, history and provenance

The host previously enriched `user` with Region/original-task/progress blocks, then the journal hashed that enriched text against UI history containing the original user text. A completed Continue could start an empty journal while restoring Confirmed Task Memory referring to old observations. Strict unknown-observation validation then correctly rejected startup.

The protocol now carries exact persisted `history_user` separately from model-facing `user`. Interrupted journal entries retain that projection as journal-only metadata; it is removed from inference messages. Completed history anchors use the raw text and presented final answer. No arbitrary user-authored tags are stripped. A compact resume envelope preserves original wording, recorded changed paths, plan, deliverables, recent checks and stop reason, explicitly distinguishing implementation claims from proof. It advises inspecting the ready component and completing missing checks rather than creating another implementation without a concrete defect.

Old completed journals can be recovered only inside the host-selected logical-task directory with one matching complete history prefix, matching user turn and presented model answer. The host-only terminal status paragraph is separate from model evidence. Multiple matching candidates, changed user requirements or changed answers fail closed. Every observation body is still checksum-validated; source freshness and Ledger binding are unchanged. A failed Task Memory startup restores the previous active journal anchor rather than poisoning it with the empty attempt. Task edit/regenerate/project-scope changes still archive/reset evidence through the existing host path.

### Ordinary Chat 50K

The old source and installed backend had a 32,768 per-request cap, plus context reservation; ordinary Chat stopped on `finish_reason=length` without aggregate continuation. No hard-coded 16K ceiling or exact historical 15,711-token request was recovered. Context availability/reasoning can reduce visible output; an exact historical cause cannot be established from that count alone.

Chat now has a **50,000 aggregate output-token budget**, retaining the backend per-request cap and actual available context. Only technical length termination with useful new content initiates continuation. Synthetic continuation turns stay inference-only; all visible pieces persist in one assistant message. A bounded suffix/prefix buffer removes repeated boundaries, retaining Markdown/code-fence state; empty/repeated progress and a request safety bound stop further continuation. Natural EOS does not continue. Reasoning stays separate. Stop/backend/context failures durably retain partial output. The UI reports the budget/context/progress limit and offers Continue answer. Explicit manual continuation follows the existing new user-turn architecture, rather than appending to the old message.

This is a maximum budget, not a promise of 50K with a smaller context. It uses backend completion accounting when available and a conservative estimate otherwise. No expensive real 50K generation was run. Agent step/output budgets remain unchanged; the agent continuity/tool fixes above are separate changes.

## Test isolation and limitations

They wrote diagnostics to `runtime/logs/application.log`, `runtime/protected-runtime.json` and `runtime/protected-runtime-events.jsonl`. There is no pre-run snapshot allowing exact byte/record attribution; the existing files must not be presented as wholly test-created. No cleanup or rewriting of those records was attempted. There is no evidence these tests edited model profiles, GGUF or user chat history, and no such actions were authorized.

The affected Node entry points now import test isolation before application singletons. With no explicit override they allocate separate `mkdtemp` runtime roots. A regression executes all three actual entries concurrently, checks distinct roots and verifies the existing user diagnostic files' hashes/sizes remain unchanged. Temporary roots are retained as owned diagnostic artifacts; no cleanup traverses user runtime.

## Reproduction controls

`prepare-online-shop-qwen.mjs` requires an explicit `LOCAL_AI_TEST_SHOP_SOURCE` and free GPU memory. It copies source and dependencies into a new temporary project, records source hashes, and starts only its owned loopback model server. `--verification-baseline` explicitly seeds the reconstructed delivery contract; omit it for a new coding experiment. Never present that seed as model-authored code.

Before `online-shop-qwen-acceptance.mjs`, copy the built Rust executable into a new immutable fixture directory with basename `local-ai-agent-runtime` and set `LOCAL_AI_AGENT_RUNTIME` to that snapshot. `--verification-only` asks the real model to verify the seeded implementation; `--continue` / `--formal-check` require the existing task and `task.json`. The runner checks server health, records actual request JSON/SSE, run actions, and checkpoints, and preserves the original Region. It now checkpoints during the observation loop and handles normal SIGINT/SIGTERM through the same Stop/cleanup path. Hard process termination can still interrupt harness-owned proxy transport; it cannot be treated as a model failure. Raw artifacts remain private temporary data; only the sanitized control summary is committed. Browser approvals must be handled in the normal UI by the user, not automatically accepted by the harness.
