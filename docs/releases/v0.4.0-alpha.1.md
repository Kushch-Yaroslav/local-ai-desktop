# Local AI Desktop v0.4.0-alpha.1

## English

**An experimental technical checkpoint, not a stable or completed user release.** It preserves the current Goose-based v0.4.0 migration state. The project is moving from the previous Local AI Desktop architecture to the Goose Rust agent runtime and Electron/React desktop. Not all features or data compatibility from v0.3.2.0 have been migrated. Live Browser and other previous-version features remain in development.

The project's priority is running an AI agent locally on the user's hardware. Local AI Desktop includes its own managed `llama.cpp` / `llama-server` integration for GGUF models, so local inference does not require Ollama or a cloud inference service. Goose also supports local model providers; this downstream integration adds Local AI Desktop's particular runtime management and profile workflows.

This checkpoint includes:

- GGUF profiles with controls for model loading and runtime parameters.
- Maximum Context Discovery with real `llama-server` startup, health and inference probes, plus RAM and VRAM budgeting. Results are measured for a specific model, runtime and configuration; they are not universal guarantees.
- FP16 and Q8 KV-cache settings, Flash Attention and GPU layer controls, subject to the selected runtime's advertised capabilities.
- Embedded MTP for compatible models and model metadata.
- Thinking and Reasoning Effort controls that use confirmed provider/model capabilities instead of inventing unsupported options.
- Vision through `mmproj` for compatible models and runtimes.
- Experimental MoE GPU expert-cache placement for an audited Qwen3-Coder-Next-80B Q4_K_M configuration. This remains configuration-specific; it is not general support for every MoE model, and some cache, Vision and MTP combinations are intentionally rejected.
- Goose agent runtime capabilities, including tool use and project-based work.

The Linux x64 checkpoint package contains the application-managed llama.cpp runtime and CUDA runtime libraries. That CUDA build targets NVIDIA sm_86 and requires a compatible host NVIDIA driver. Model weights are not included. The bundled llama.cpp runtime is a separate Local AI Desktop integration; Goose itself has local model support, but does not provide this same managed runtime/profile implementation.

## Русский

**Экспериментальная техническая контрольная версия, а не стабильный или завершённый пользовательский релиз.** Она сохраняет текущее состояние миграции v0.4.0 на Goose. Проект переходит со старой архитектуры Local AI Desktop на Rust agent runtime Goose и Electron/React UI. Перенесены ещё не все функции и форматы данных v0.3.2.0. Live Browser и дополнительные функции прежней версии остаются в разработке.

Приоритет проекта — работа AI-агента локально на оборудовании пользователя. В Local AI Desktop добавлена собственная интеграция `llama.cpp` / `llama-server` с управлением GGUF-моделями; для локального inference не требуются Ollama или облачный inference-сервис. Goose также поддерживает локальные model providers; эта downstream-интеграция добавляет конкретные механизмы управления runtime и профилями Local AI Desktop.

В контрольной версии доступны:

- GGUF-профили с настройками загрузки модели и параметров runtime.
- Maximum Context Discovery с реальными пробами запуска `llama-server`, проверки готовности и inference, а также с расчётом бюджета RAM и VRAM. Результаты измеряются для конкретной модели, runtime и конфигурации и не являются универсальной гарантией.
- Настройки KV-cache FP16 и Q8, Flash Attention и количества GPU Layers с учётом возможностей, объявленных выбранным runtime.
- Embedded MTP для совместимых моделей и метаданных.
- Настройки Thinking и Reasoning Effort, которые опираются на подтверждённые возможности provider/model и не предлагают неподдерживаемые значения.
- Vision через `mmproj` для совместимых моделей и runtime.
- Экспериментальное размещение GPU expert cache для проверенной конфигурации Qwen3-Coder-Next-80B Q4_K_M. Поддержка зависит от конфигурации; это не общее обещание для всех MoE-моделей. Некоторые сочетания cache, Vision и MTP намеренно отклоняются.
- Возможности Goose agent runtime, включая работу с инструментами и проектами.

В Linux x64 checkpoint-пакет включён управляемый приложением llama.cpp runtime и библиотеки CUDA runtime. Сборка CUDA нацелена на NVIDIA sm_86 и требует совместимого драйвера NVIDIA на хосте. Веса моделей в пакет не входят. Встроенная интеграция llama.cpp — отдельная часть Local AI Desktop: Goose поддерживает локальные модели, но не предоставляет такой же механизм управления runtime и GGUF-профилями.
