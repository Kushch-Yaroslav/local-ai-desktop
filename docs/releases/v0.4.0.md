# Local AI Desktop v0.4.0

Stable release, following the `v0.4.0-alpha.1` Goose migration checkpoint.

## Highlights

- **Goose-based desktop agent workspace.** The Electron/React application uses Goose's Rust agent runtime and offers distinct Chat and Agent modes.
- **Local GGUF inference.** The Linux x64 package bundles the integrated llama.cpp runtime. Users supply their own model files.
- **Inference controls and maximum context discovery.** Configure supported model/runtime parameters, including KV cache, Flash Attention, and CPU/GPU offload. Context discovery probes a specific model and configuration against available memory.
- **Qwen MTP speculative decoding.** MTP controls and discovery support are available for compatible Qwen models and runtime metadata.
- **Native Live Browser.** The Electron WebContentsView shares its page with Playwright and Goose MCP browser tools. Users can select visual regions, track findings, and attach typed browser context to a conversation.
- **Ubuntu packaging and launcher work.** The x64 `.deb` bundles the Electron app, Goose backend, Node/Playwright browser runtime, and integrated llama.cpp resources. Launcher identity and AppArmor guidance are included.

## Improvements

- Improved model-profile and inference-setting feedback, including clearer diagnostics for runtime startup and maximum-context discovery failures.
- Added controls for project-directory selection and Vision On/Off, and made browser context attachments retain their typed identity through chat history and retries.
- Improved the Live Browser workspace with native page controls, region/finding inspection, bounded evidence history, responsive layouts, and localized UI strings.
- Improved Ubuntu Desktop Entry and package activation checks, bundled a supported Node runtime for browser automation, and retained Chromium's sandbox.
- Added Chat/Agent provider and runtime checks. Tests distinguish model text that resembles a tool call from structured calls dispatched to tools.

## Known Limitations

- Model behavior, memory use, maximum context, GPU offload, Flash Attention, and MTP support vary with the GGUF, runtime build, driver, and hardware. Discovery results describe the tested configuration; they do not guarantee that every later prompt or longer run will fit or remain stable.
- Live Browser is intended for local project workflows, not as a secure general-purpose browser. Page content can be inaccurate or hostile. Visual-region selection and evidence checks do not establish full parity with the original Visual Debugger, and the release does not claim autonomous verification of arbitrary CSS fixes. Real-model acceptance covers specific Qwen and browser flows, not every model, project, or display configuration.
- Chat mode does not dispatch structured tool calls through the Goose runtime. A model can still write text that looks like a command or tool call; that text is not execution. Agent operations can affect selected project files and follow the configured tool-approval policy, so review changes and approvals.
- Ubuntu 24.04 x64 is the primary tested target. Other distributions, GPU/driver combinations, and model/context configurations have not been validated broadly.
- Some advanced GGUF controls are not translated in every locale yet and can fall back to English; the localization completeness check still reports untranslated `gguf.*` labels.
- GGUF weights are not included. Legacy v0.3.x features and stored-data formats are not all carried into the Goose-based v0.4 line; keep any older installation and its data until you have confirmed what you need.

## Installation

Download `local-ai-desktop_0.4.0_amd64.deb` and `SHA256SUMS` from the [GitHub Release](https://github.com/Kushch-Yaroslav/local-ai-desktop/releases/tag/v0.4.0). Verify and install on Ubuntu:

```sh
sha256sum -c SHA256SUMS
sudo apt install ./local-ai-desktop_0.4.0_amd64.deb
```

APT installs the package's declared system dependencies. The package includes Electron, Goose, the browser's Node/Playwright runtime, llama.cpp, and its packaged runtime libraries. It does not include user GGUF models; add compatible local files in the app. Do not launch the app with `sudo`.

### Ubuntu AppArmor user-namespace rule

On Ubuntu installations where `sysctl -n kernel.apparmor_restrict_unprivileged_userns` returns `1`, Chromium may need permission to create a user namespace. Install a rule for the packaged executable:

```sh
sudo tee /etc/apparmor.d/local-ai-desktop <<'EOF'
abi <abi/4.0>,
include <tunables/global>
profile local-ai-desktop "/usr/lib/local-ai-desktop/local-ai-desktop" flags=(unconfined) {
  userns,
}
EOF
sudo apparmor_parser -r /etc/apparmor.d/local-ai-desktop
```

This grants the `userns` permission to the Local AI Desktop executable while leaving Chromium's sandbox enabled. If you later uninstall the package, unload and remove the rule with `sudo apparmor_parser -R /etc/apparmor.d/local-ai-desktop` followed by `sudo rm /etc/apparmor.d/local-ai-desktop`.

## Integrity

The release includes a `SHA256SUMS` file for the published package. No GGUF weights, user profiles, chats, credentials, local logs, test projects, or Cargo build caches are release assets.
