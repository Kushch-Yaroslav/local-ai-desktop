# Local AI Desktop v0.3.0

**Experimental Alpha · 29 October 2026**

v0.3.0 adds a Browser Workspace beside Chat and Agent, tools for selecting parts of a page, and more reliable work with long text documents. Agent tasks, model setup and recovery also received substantial improvements.

## Browser Workspace

Open a local web project next to Chat or Agent and view the page inside the app. Start the project's development server in your usual way, for example with `npm run dev`, then enter its local address in Browser Workspace. The app does not necessarily start that server for you.

Choose a viewport size, including mobile and desktop previews, adjust page zoom and preview scale, and change the browser layout. You can collapse secondary panels or expand the browser to use more of the window. Browser Workspace is intended mainly for local projects; it is not presented as a secure general-purpose browser. Navigation rules do not guarantee that every external site is blocked.

![A local web project open beside Chat in Browser Workspace](../img/releases/v0.3.0/browser1.png)

## Select the parts you want to change

Choose **New area**, then drag over the relevant part of the page. Use **Add selection** to include another area, for example one element to move and another place where it should go. Review and manage the selected regions before sending them with your request.

Select the part of the page you want to change, then describe the result you want. You can also select several areas to show where content should move.

The selection gives Chat or Agent region details and, where available, related page elements and project sources. A text-only model does not directly see browser pixels. Actual image input depends on a vision-capable model and the app's vision settings; source and DOM evidence can help locate code but does not prove what every selected pixel looks like.

![Two selected page areas included in a request](../img/releases/v0.3.0/browser2-select-area.png)

## Read long text documents

Attach a supported text file such as a large `.txt` (individual attachments are limited to 25 MB), ask Chat to read it fully, and watch the reading progress. The app processes long documents in sequence and keeps confirmed progress so a reading task can continue after interruption. You can then ask for a summary or follow-up questions. The result depends on the model; sequential processing does not guarantee that every detail will be retained or recalled.

Text attachments include `.txt`, `.md`, `.json`, `.csv`, `.log` and supported source/configuration text files. Other supported attachments have their own extraction paths; this whole-document workflow should not be assumed for every format. Scanned PDFs need OCR, which the app does not provide.

![A long TXT document being read with progress shown in a compact Chat view](../img/releases/v0.3.0/book.png)

Collapse the conversation history or other secondary panels when you want more room for the current task.

## Chat and Agent improvements

Chat can use read-only tools to inspect supported attachments and, when you choose a project, search its files and read bounded source ranges. It can also inspect the already-open Browser Workspace. Project writes, terminal commands and browser interaction remain Agent actions. Large attachment reading, progress, notes and recovery after Stop, compaction or restart are more reliable.

Agent Runtime V2 keeps task plans and results available as work continues across chats. Recovery from repeated actions is bounded, and verification distinguishes what the Agent reports from checks backed by fresh evidence. A completed plan is not itself proof that every result is correct; review the changes and checks.

Long Chat answers can continue across model requests within an orchestration budget of up to 50K output tokens. This is not a promise that a model will produce that much text. The Context Monitor shows measured usage and activity, while compaction preserves the current user request and reading progress more reliably.

## Model setup and interface

Model profiles, GGUF availability refresh, context controls and recovery after runtime errors are clearer. Linux can refresh model availability after you mount a removable drive. The interface also gives more space to the current task by letting you collapse secondary panels.

## Install or update

Download the Linux amd64 package from the [v0.3.0 GitHub Release](https://github.com/Kushch-Yaroslav/local-ai-desktop/releases/tag/v0.3.0) and verify it with the included `SHA256SUMS` file. Install or update with:

```sh
sudo apt install ./local-ai-desktop_0.3.0_amd64.deb
```

The package does not include `llama.cpp`, GGUF weights or model projectors. Back up application data before upgrading. Never run the app as root. Agent terminal access requires the administrator-managed Bubblewrap and enforcing AppArmor setup described in [Getting started](../en/GETTING_STARTED.md).

## Compatibility and limitations

This is an **Experimental Alpha** for Linux x86_64. Ubuntu 24.04 is the primary tested environment; other distributions, hardware and drivers have not been broadly validated. Browser Workspace is intended primarily for local development previews and is not a security boundary for general web browsing. Agent can change real project files, so review changes and keep backups. Model support and answer quality depend on the model, runtime, available memory and task. See the [user guide](../en/USER_GUIDE.md) for the controls and workflow details.
