# Browser Workspace, GGUF availability and safe preview recovery

## Confirmed diagnosis

Read-only host diagnostics on 2026-10-25 found the NTFS volume referenced by the two unavailable model profiles present as a block device, **unmounted**, with its `/media/<user>/<volume>` directory absent. Udisks' boot journal reported cleaning up this mount point because the device was not mounted. The separate DATA volume was mounted. Both saved absolute model paths returned ENOENT on the host, independently of the sandbox.

This establishes the current unavailable-storage cause. It does not prove when the disk was mounted during earlier launches, that the files exist inside the currently unmounted filesystem, or why Ubuntu did not mount it. No mounting, filesystem repair, driver changes, model loading or profile edits were performed. The common GGUF directory was never a restriction on absolute paths. Refresh already performed fresh validation; it could not make an unmounted volume available.

Availability now distinguishes a missing removable-media root, a missing file under an available directory, access denial and other I/O errors. It retains the original error details. The media-root classification covers Ubuntu `/media/user/volume` and `/run/media/user/volume`; an arbitrary custom mount location cannot be reliably inferred from ENOENT. Split shards and mmproj retain their existing validation. The refresh button updates model discovery without saving profiles or starting/stopping weights. The default GGUF folder is a collapsed advanced setting for the chooser and relative paths.

## Build and preview contract

A real React/Vite fixture demonstrated that successful `npm run build` leaves the existing dev server alive. A failed strict-port production preview also leaves that server alive. The reported `/dist/index.html` navigation was therefore an unsafe fallback, not evidence that build killed the dev server. The user's exact old inference trace was not available in the source test runtime; this is a reproduced failure path, not a claim about unseen tool decisions.

A second, independently reproduced bug affected freshness after build: the project watcher counted generated build HTML/CSS/JS as source changes, while Vite correctly ignored its output directory. It could then mark an already white live DOM as possibly stale. The watcher may start before Vite is identified; identification now also updates its existing output exclusions. Only Vite build output directories are excluded, preserving ordinary static-project autoreload. Bounded literal config inspection ignores comments/string contents and never evaluates code. Unresolvable dynamic output directories remain conservative rather than assumed fresh. The final fixture uses the same real Vite config for dev and build and asserts both white computed CSS and non-stale freshness after build.

`web_project preview_status` checks the original region URL (or the existing run's original Page) using bounded GET requests to the already approved exact loopback origin. It checks HTML plus up to four same-origin entry JS/CSS assets, with a six-second total request deadline and existing response limits. It neither navigates nor changes viewport/zoom/presentation. HTTP health, Native Page freshness and process ownership are separate fields. Responding HTML is **not** proof of mounted React, working HMR or a verified visual defect.

The Vite dev-server path refuses built HTML before navigation: default `dist/index.html`, `build/index.html`, and literal `build.outDir` values read from bounded, project-confined JS/TS Vite config files. Config is never executed. Dynamically computed output directories cannot be inferred by this literal reader. Production preview requires a genuinely running, explicitly authorized origin; failure is not converted into successful QA. The isolated QA navigation callback applies the same build-path check. Normal completion of a region run restores its existing user's original route after supplementary navigation, if the original HTML is reachable. Stop does not trigger this navigation. Workspace settings are not reset.

With Testing and verification ON, the additional instruction explains health checks and safe recovery. OFF removes that instruction and leaves the diagnostic/browser tools available. There is no language-to-command executor: the model must inspect actual scripts, lockfiles and project configuration. No unconditional restart was added.

Recovery uses the existing approved `task_action` lifecycle. Only an existing, current-generation owned handle can be stopped; neither a listening port nor a PID proves ownership. External and unknown servers are never adopted or terminated. Missing scripts are not invented and ports are not silently changed. **Existing managed tasks are run-scoped and cleaned up on completion/Stop. This change does not introduce a persistent background dev-server supervisor or promise that a run-scoped restarted server survives task completion.** Where safe durable recovery is unavailable, preserve the Page and report that the server needs owner action. The fixture's same-port restart is performed by its own `createServer` handle; it is not presented as an autonomous app-owned restart acceptance.

Repeated refused build fallbacks and unreachable-preview calls join the existing bounded browser recovery guard and resumable Stop. A successful health probe is not inserted as formal Verification Ledger coverage.

## Workspace and current area numbers

Viewport, page zoom, presentation mode (Fit / Scroll), and preview scale are visible together. Fit uses the available bounds without changing the fixed CSS viewport. Scroll uses the remembered numeric preview scale and enables the existing pan/scrollbar surface. Native zoom, DPR, capture/masking and input conversion remain in their existing implementations.

The header switches Vertical / Horizontal. Vertical tools occupy a bounded scrollable row (up to 260 px / 40%); new issue cards scroll inside it. Horizontal tools use a left sidebar with pointer and keyboard resize, 220–520 px, and preserve a minimum right surface. Below 650 px panel width the layout adapts to vertical without discarding the user's horizontal preference. Mode, preferred width and preview scale use the existing chat visual-document SQLite workspace persistence. Switching layout does not recreate the WebContentsView or Page.

Current issue numbers are contiguous in document order. Delete all, then create: Area 1. UUIDs and group IDs remain immutable. Existing chat-message reference copies retain their historical number and UUID; revealing a deleted historical reference reports it deleted, never points to a new Area 1. Draft-only empty areas remain transient. Color and source evidence remain attached to the original IDs.
