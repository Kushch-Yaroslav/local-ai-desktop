Рабочая ветка: `feature/v0.3-browser-vision-qa`, база P1 `4c6d8bb`. Версии, main, теги, установленный .deb и пользовательские проекты не изменялись. Исходный незакоммиченный каталог `runtime/` сохранён. Анализ до реализации: [технический план](v0.3-p2-technical-plan.md).

## Архитектура и подтверждение Vision

Выбран Hybrid: Playwright проверяет реальное поведение, встроенная мультимодальная Qwen анализирует выборочные PNG. Используется существующая Page; отдельного браузера и второй большой модели нет. Внешний llama-server 0.4.1-dev, commit `d1d3c3396aa13a5f239109a822666c4870490ad5`, HTTP/SSE. Изображения передаются как реальные base64 image_url, после проверки размеров, SHA256 и принадлежности capture. Путь к файлу не подменяет изображение.

Проверены обе локальные модели: `qwen3.8-27b-q4_K_M.gguf` + `qwen3.8-27b-mmproj.gguf` и `Qwen3.6-35B-A3B-UD-Q4_K_M.gguf` + `mmproj-BF16.gguf`. Отдельный совместимый projector необходим: примерно 889 и 861 MiB на диске соответственно. CPU projector, CUDA target; для MoE сохранены четыре CPU expert layers. Модели и веса не скачивались и не менялись.

Обе модели правильно распознали только пиксельные синий квадрат, красный треугольник и жёлтый круг. В DOM и тексте запроса этих сведений не было. Одновременно backend подтвердил draft-mtp и реальные accepted tokens. Следовательно, отключение MTP для этих известных конфигураций не требуется. Поддержка устанавливается по известной архитектуре/весам и фактическому `models[].capabilities` запущенного backend; одного имени файла недостаточно. Для неизвестных конфигураций нет обещания совместимости.

## Жизненный цикл

Browser Vision Off/Auto/On сохраняется независимо от Autonomous Browser QA. Off запрещает передачу снимков этому provider; Auto использует только уже совместимый backend без повторных попыток загрузки. On проверяет доступность; при необходимости собственный диалог подтверждает перезагрузку той же модели с совместимым projector. Нет автоматического Stop, скачивания, смены coding-модели или отключения MTP. Активная генерация в любом чате блокирует reload. QA переключается отдельно и не перезагружает модель.

Reload пересоздаёт процесс inference/context/KV-cache. SQLite-история, Task Memory, план и завершённые результаты инструментов сохраняются. Pause прерывает длительный анализ изображения через существующую кооперативную отмену, не закрывая Page. Resume продолжает агентную задачу из checkpoint, а не незавершённый KV stream. Закрытие браузера отменяет pending analysis. Новые run сбрасывают run-local бюджеты и требуют действующих разрешений.

Реальный production controller: On → Off → Auto → Off, CPU projector, 16K Q8. В каждом режиме получен native ответ; в On/Auto анализировался реальный browser capture, в Off изображение не отправлялось. Все четыре owned PID завершились. Pause 41.73 ms; после reload Resume не повторил успешное изменение файла.

## QA и Verification Gate

Инструмент `web_project` получил `qa` и capture viewport/clip/element. Сохраняются URL, viewport, размеры, координаты, timestamp, capture latency, SHA256, PNG и JSON. Проверки выполняются настоящим Chromium: загрузка, uncaught errors, console errors, unhandled rejections, offscreen controls, click/fill/key/scroll с ожидаемым текстом/значением/изменением состояния. Canvas: реальный фокус, WASD с удержанием, pointer drag, доставленные события, продолжение RAF/draw после действий, NaN/Infinity в наблюдаемых аргументах и optional `window.__qaDiagnostics`. Наличие event handler в исходнике не считается результатом.

Для Canvas недостаточно изменения кадров: без passed семантического oracle от key/canvas click результат частичный. Vision получает пару до/после, а не только конечный кадр. Одинаковые кадры дедуплицируются. Максимум 4 анализа/run, интервал 1.5 s, 1280×900, 2 MiB/image, timeout 60 s, 768 output tokens. Нет потока Live Browser в LLM. Вывод структурированный: confidence, конкретные issues, основание. Ошибка/timeout/невалидный JSON означает Not Verified и функциональный fallback.

Gate встроен в существующий Rust verification review. Он учитывает изменённые web-файлы и browser actions, требует свежий interaction report и не принимает одиночный screenshot за функциональную проверку. Изменение исходников инвалидирует evidence. Максимум три QA review, затем честный остаточный статус. Явный security deny не вызывает автоматического повторного запроса. При недоступном web инструменте — Blocked, без обхода через terminal. Результаты и source epoch сохраняются в Task Memory/checkpoint. Статусы Verified, Partially Verified, Failed, Blocked, Not Verified; functionalStatus и visual status разделены.

## Реально найденные и исправленные дефекты

* Тестовый Canvas бросал `camera rotation defect` после движения мыши и останавливал animation. Qwen сама вызвала QA, получила errors/замершие RAF и draw counters, прочитала файл, выполнила exact-match replace_text, повторила QA. Проверены button, input и изменение camera state от клавиши и canvas click. Ошибки исчезли, RAF/draw продолжились; итог Verified с реальным парным Vision. Пользовательский NEXUS не изменялся.
* В ранней реализации сравнение кадров только до взаимодействия пропускало последующее зависание. Проверка перенесена после завершения действий.
* Найден реальный формат llama-server capability: root models[], а не только OpenAI data[]. Добавлена регрессия.
* Старый capture мог ошибочно удовлетворять gate после изменения файла. Теперь требуется свежий interaction report/source epoch; сохранённый результат не теряется, но не считается актуальным.
* Во время UI проверки исправлены focus return/trap, доступное имя контекста и сжатие верхней строки узкого окна.

[Реальный Qwen fix/retest](test-results/p2/qwen-real-qa.json): контекст32768 Q8, MTP1716 drafted/1388 accepted (80.89%, lifetime server), оба QA передали по два изображения, по2410 prompt tokens, анализ32.24/33.40 s, capture27.67–60.30 ms. Image-only challenge1.91 s. Pause во время Vision56.80 ms, Resume сохранил checkpoint. GPU18709 MiB, process RSS10837032 KiB (~10.34 GiB), observed high-water16791736 KiB (~16.01 GiB). Последние два показателя включают длинный тест, не только projector. Не следует выводить из них стоимость одной картинки.

Во время калибровки harness были отклонены protected project path и неверный request; это не обходилось. Один повторный запуск теста пересёкся с ещё освобождающим GPU owned процессом и получил OOM. Добавлены preflight свободной VRAM и bounded teardown только собственных PID. Установленная версия приложения не затрагивалась. Две большие модели одновременно не запускались.

## UI/UX

Панель сгруппирована: Model & Inference, Reasoning & Agent, Browser & QA, Projects & References. Сохранились тёплая тема и существующие токены. Выбор модели/контекста сначала staged, затем явное применение. Различаются Live, After response и Reload; requested/pending/applied не смешаны. Реакция на другие активные чаты, pause/loading/error, компактные status и уведомления вне истории. Vision и QA независимы.

Единый native Chromium dialog в приложении (не window.confirm): focus trap, Escape, возврат фокуса, Cancel/Primary, подробности, честное предупреждение KV-cache. Tooltip поддерживает клавиатуру и portal. Выразительные disabled/focus/hover, умеренные transition, reduced-motion. Панель ограничена по высоте и прокручивается; QA показывает действия и evidence, восстанавливается из SQLite после reload. Большого отдельного dashboard нет.

## Ограничения и готовность

Готово к контролируемому пользовательскому тестированию, без merge/release. Полный агентный цикл проверен на dense Qwen; MoE проверена только image-only+MTP. Не сертифицированы другие GPU/backend/projector/max-context профили. Generic Canvas instrumentation не доказывает семантику произвольной игры, WebGPU/OffscreenCanvas и закрытого состояния; нужны явные ожидаемые изменения. Vision может давать субъективные false positives (например оценка clipping); confidence — оценка модели, не статистическая гарантия. Нет обещания бесшовного KV-cache resume. Нет второй vision-модели, непрерывного LLM video, автоматических downloads и изменений пользовательского NEXUS. Optional overlay проблемного DOM-элемента не реализован. UI проверен RU/EN; полный визуальный аудит остальных локализаций/тем не проводился.
