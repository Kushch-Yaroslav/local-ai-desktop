# Начало работы

[English](../en/GETTING_STARTED.md) · [Русский](GETTING_STARTED.md) · [Главная](../../README.ru.md)

## Перед началом

Опубликованное приложение рассчитано на Linux x86_64. Основная проверенная среда — Ubuntu 24.04. Для amd64 Debian-пакета нужны Bubblewrap версии 0.9.0 или новее и AppArmor версии 4.0.0 или новее; `apt` установит эти системные зависимости, если доступны совместимые версии. Пакет включает приложение и Agent runtime, но не `llama.cpp` и не веса модели. Отдельно установите совместимый `llama-server` и получите модель GGUF. Другие дистрибутивы Linux, ARM, GPU, драйверы и окружения рабочего стола требуют отдельной проверки.

Командам Agent в терминале нужны Bubblewrap, Linux user namespaces и защита AppArmor в режиме enforcing. Не отключайте AppArmor или ограничения user namespaces ради запуска терминала. Если нужная изоляция недоступна, выполнение команд будет заблокировано. Чат и поддерживаемые файловые функции при этом доступны.

## Установка или обновление до v0.3.1

Скачайте `local-ai-desktop_0.3.1_amd64.deb` и `SHA256SUMS` со [страницы релиза v0.3.1 на GitHub](https://github.com/Kushch-Yaroslav/local-ai-desktop/releases/tag/v0.3.1). В каталоге загрузки проверьте пакет и установите его:

```sh
sha256sum -c SHA256SUMS
sudo apt install ./local-ai-desktop_0.3.1_amd64.deb
```

Эта команда с правами администратора устанавливает пакет и системные зависимости, настраивает управляемый helper Agent и профили AppArmor. Ознакомьтесь с пакетом и подтвердите системные изменения менеджеру пакетов. Само приложение Local AI Desktop нельзя запускать от `root`.

После успешной настройки пакета администратор должен разрешить нужной desktop-учётной записи использовать отдельную группу helper:

```sh
sudo adduser ACCOUNT local-ai-desktop
```

Замените `ACCOUNT` именем этой учётной записи. Добавляйте только пользователей, которым нужен терминал Agent. Чтобы изменение группы вступило в силу, пользователь должен выйти из системы и войти снова. При ошибке настройки пакета или policy не обходите защиту: исправьте настройку пакета до использования терминала Agent.

## Установка из исходников

Используйте эту процедуру только для работы из исходного репозитория. Не применяйте её для управления Debian-пакетом. Из корня репозитория сначала выполните неповышенную по правам проверку policy:

```sh
installer="$PWD/scripts/install-bwrap-apparmor.sh"
test -n "$installer"
bash "$installer" --check
```

Если проверка прошла, администратор может установить helper для основной группы текущего пользователя:

```sh
sudo /bin/bash "$installer" --install --group "$(id -gn)"
```

Для шага с правами администратора нужна существующая группа, отличная от root, ожидаемый системный Bubblewrap с владельцем root, принятая policy AppArmor и отсутствие конфликтующих управляемых файлов. Устанавливается отдельный helper, принадлежащий root и не имеющий setuid, после чего загружаются два enforcing-профиля. `/usr/bin/bwrap`, глобальные параметры защиты и группы не меняются. Выбранная группа получает доступ к helper, поэтому используйте только группу с подходящим составом участников. Если установщик обнаружил существующий конфликт policy или helper, остановитесь и попросите администратора проверить файлы; не удаляйте и не перезаписывайте их вслепую. Автоматического отката у установщика нет.

Чтобы проверить режим enforcing у обоих профилей, выполните:

```sh
sudo grep -E '^local_ai_desktop_bwrap(_child)? \(enforce\)$' /sys/kernel/security/apparmor/profiles
```

В выводе должны быть `local_ai_desktop_bwrap (enforce)` и `local_ai_desktop_bwrap_child (enforce)`. Пакетная установка обновляет управляемый helper после обновления системного Bubblewrap. При ошибке helper остаётся недоступным, пока администратор не исправит пакет. Подробности приведены в [технической процедуре установки](../bwrap-installation-acceptance.md).

## Настройка модели

1. Установите или соберите версию `llama-server`, совместимую с вашей моделью GGUF и оборудованием. Приложение не скачивает сервер, веса или projector.
2. Откройте **Настройки → Модели и runtime** и укажите **Путь к llama-server или его папке**.
3. Выберите каталог моделей и нужный файл GGUF. Projector нужен только некоторым моделям.
4. Выберите модель на панели, затем размер контекста и KV-кэш FP16 или Q8. Явно загрузите выбранную конфигурацию.
5. Дождитесь готовности runtime и отправьте короткое сообщение в Chat.

![Настройки runtime модели](../img/settings.png)

Значение GPU layers `999` запрашивает максимальный offload, поддерживаемый backend; `0` — слои на CPU. При необходимости частичный offload на CPU/GPU нужно настроить явно. После ошибки загрузки автоматический переход на меньший контекст или меньшее число GPU-слоёв не гарантируется. Свободная память сама по себе не гарантирует успешную загрузку.

## Первая задача Agent

Выберите временный проект, переключитесь в Agent и попросите выполнить небольшую задачу, например прочитать файл или внести ограниченное изменение и запустить тесты. Режим **Запрашивать подтверждение** поможет разобраться, какие действия предлагает Agent. В «Абсолютном автопилоте» действуют те же обязательные границы, а некоторые действия всё равно могут быть заблокированы. Проверяйте изменения самостоятельно; универсального отката нет.

## Запуск из исходников

Для разработки нужны Node.js 24, npm 10 или 11, Rust toolchain, совместимый с зафиксированными зависимостями, и средства сборки Linux. Из корня репозитория выполните:

```sh
npm ci
npm run build
npm start
```

`npm run dev` собирает Rust Agent runtime и запускает приложение для разработки. Не заменяйте исполняемый файл runtime во время Agent-задачи. Перед сборкой завершите или остановите свою задачу, после сборки штатно перезапустите приложение. Запускайте команды разработки от своего пользователя, не через `sudo`.

## Данные и обновления

Новая установка хранит данные в `~/.local/share/local-ai-desktop`, настройки — в `~/.config/local-ai-desktop`, кэш — в `~/.cache/local-ai-desktop`, журналы — в `~/.local/state/local-ai-desktop/logs` (если не заданы соответствующие переменные XDG).

Перед обновлением закройте приложение и сохраните копии каталога данных и настроек, включая базу данных и вложения. Если путь модели устарел, исправьте активный профиль в Settings; не перезаписывайте другой файл настроек. Миграция базы не может восстановить историю задач, которая раньше не сохранялась. Не понижайте версию базы после миграции без восстановления соответствующей резервной копии.

## Диагностика

- **Терминал Agent сообщает, что изоляция недоступна:** попросите администратора проверить настройку пакета, отдельный helper и оба enforcing-профиля AppArmor. Смена режима разрешений не исправляет изоляцию.
- **Helper больше не совпадает с системным Bubblewrap:** администратору нужно обновить или восстановить управляемый helper. Приложение намеренно не запускает команды в shell хоста.
- **Сервер модели выключен или не отвечает:** проверьте его путь и журналы runtime, выберите модель и явно загрузите её настройки.
- **При загрузке не хватает памяти:** попробуйте поддерживаемый меньший контекст, другой тип KV-кэша или явно настройте GPU layers. Восстановление после полного исчерпания памяти не гарантируется.
- **Не работает изображение:** проверьте поддержку vision у модели и наличие требуемого файла projector.

Продолжение — в [Руководстве пользователя](USER_GUIDE.md).
