# Начало работы

[English](../en/GETTING_STARTED.md) · [Русский](GETTING_STARTED.md) · [Главная](../../README.ru.md)

## Требования

Изоляция Agent реализована для Linux x86_64; основная проверенная среда — Ubuntu 24.04 с Bubblewrap 0.9.0. Debian-пакет включает Electron и Rust Agent Runtime, но не llama.cpp и веса GGUF. Другие дистрибутивы, ARM, драйверы и окружения рабочего стола требуют отдельной проверки. RTX 3090 24 ГБ, Ryzen 7 5700X3D и 64 ГБ RAM разработчика — тестовая конфигурация, не минимальные требования.

Опубликованные пакеты доступны на [GitHub Releases](https://github.com/Kushch-Yaroslav/local-ai-desktop/releases). Установленный v0.2.0 прошёл приёмку на Ubuntu разработчика; независимая установка на чистую ОС не проверялась.

## Установка последнего опубликованного пакета

Скачайте amd64 `.deb` со [страницы Experimental Alpha v0.2.0](https://github.com/Kushch-Yaroslav/local-ai-desktop/releases/tag/v0.2.0) и установите:

```sh
sudo apt install ./local-ai-desktop_0.2.0_amd64.deb
```

Команда устанавливает пакет и зависимости. Не запускайте Electron от root. При конфигурации пакет устанавливает отдельный helper и загружает профили AppArmor. Администратор должен явно разрешить нужной desktop-учётной записи доступ через отдельную группу, как описано ниже. При отказе изоляции выполнение блокируется; перехода к shell хоста нет.

## Требования терминала Agent на Ubuntu

Проверенная конфигурация требует системный Bubblewrap, включённые AppArmor/user namespaces и отдельные enforcing policy/helper приложения. Не отключайте глобальные ограничения AppArmor/user namespaces ради запуска. При невозможности безопасного старта терминал закрыт по умолчанию; работа файловых инструментов не доказывает его готовность.

Для пакетной установки администратор разрешает нужную учётную запись командой `sudo adduser ACCOUNT local-ai-desktop`; затем нужно выйти из сеанса и войти снова. Сначала должна успешно завершиться конфигурация пакета. Изменённые локальные policy и неуправляемые helper требуют проверки, а не автоматической замены. Не совмещайте пакетное управление с source installer.

Только для source checkout запустите проверенный отдельный installer из корня репозитория:

```sh
installer="$PWD/scripts/install-bwrap-apparmor.sh"
test -n "$installer"
bash "$installer" --check
sudo /bin/bash "$installer" --install --group "$(id -gn)"
```

Создаётся копия `/usr/bin/bwrap` в `/usr/lib/local-ai-desktop/bwrap` (root:группа-приложения, 0750, без setuid), записывается `/etc/apparmor.d/local-ai-desktop-bwrap` (root:root, 0644), загружаются и проверяются два enforcing-профиля. Системный `/usr/bin/bwrap`, глобальные настройки и группы не меняются. Установленный AppArmor parser должен поддерживать поставляемую policy. При несовпадении существующей policy installer откажет; разберите её и сохраните копию до любого отдельного обновления. Установка не выполняется автоматически и не является транзакцией.

Проверка только для чтения, если просмотр профилей требует администратора:

```sh
sudo grep -E '^local_ai_desktop_bwrap(_child)? \(enforce\)$' /sys/kernel/security/apparmor/profiles
```

Должны присутствовать оба профиля. Для пакета dpkg trigger обновляет управляемую копию после обновления системного Bubblewrap; при отказе она остаётся недоступной до исправления конфигурации. Копии для source checkout обновляет администратор проверенным установщиком. Доступ группы не удостоверяет единственного вызывающего. Развёртывание не является транзакцией с автоматическим откатом. Подробности — в [технической процедуре](../bwrap-installation-acceptance.md), читать вместе с более новой [записью проверки](../noop-loader-validation-2026-10-13.md).

## Настройка модели

1. Установите/соберите внешний совместимый `llama-server` с нужной архитектурой GGUF, GPU backend, необязательным MTP и projector.
2. Откройте **Настройки → Модели и runtime**. Укажите **Путь к llama-server или его папке**. Приложение проверяет/ищет файл в ограниченных пределах; при нескольких вариантах выберите нужный.
3. Укажите каталог моделей и реальный GGUF, projector — только если нужен. Автозагрузки весов нет. Сохраните и выберите модель в панели.
4. Явно загрузите выбранные контекст/KV, дождитесь ready и отправьте простой Chat-запрос.
5. Выберите временный проект, включите Agent и проверьте небольшую задачу чтения/правки/теста. Начните с Ask либо осознанно выберите Автопилот с теми же ограничениями.

![Настройки runtime](../img/settings.png)

GPU layers `999` запрашивает максимальный поддерживаемый offload, `0` — слои на CPU. Частичный offload настраивается намеренно, не гарантирован автоматически после OOM. NVIDIA-телеметрия использует `nvidia-smi`; для других GPU она может отсутствовать. Память зависит от весов, контекста, KV и нагрузки. При неудаче показывается ошибка backend; уменьшайте запрос явно.

## Запуск из исходников

Нужны Node.js 24, npm 10 или 11, Rust toolchain, совместимый с locked-зависимостями, и средства разработки Linux. Когда нет активной задачи, использующей пересобираемый executable:

```sh
npm ci
npm run build
npm start
```

`npm run dev` тоже собирает Rust и запускает dev renderer/main. Не пересобирайте работающий Rust executable посреди задачи; завершите/остановите свою задачу и штатно перезапустите экземпляр после сборки. Enforcing-приёмка терминала: `npm run test:sandbox-startup:electron`; она использует отдельные fixtures, без реальной модели. Тесты запускаются обычным desktop-пользователем, не через sudo.

## Данные и обновление

Новая установка использует XDG: данные — `$XDG_DATA_HOME/local-ai-desktop` (по умолчанию `~/.local/share/local-ai-desktop`), конфигурация — `$XDG_CONFIG_HOME/local-ai-desktop`, кэш — `$XDG_CACHE_HOME/local-ai-desktop`, логи — `$XDG_STATE_HOME/local-ai-desktop/logs`. Последние три default-корня: `~/.config`, `~/.cache`, `~/.local/state`. Исходная установка с `runtime/sqlite/local-ai-desktop.db` сохраняет legacy layout; `LOCAL_AI_RUNTIME_ROOT` позволяет выбрать отдельный корень экземпляра.

Перед обновлением штатно закройте свой экземпляр и сохраните реальные data/config-корни, включая SQLite и вложения. Не перезаписывайте другой файл настроек только из-за старого пути модели. Исправляйте путь активного профиля через Settings. Миграция сохраняет legacy-планы, но не восстанавливает отсутствующую принадлежность/снимки прошлого. Не понижайте версию с мигрированной базой без восстановления соответствующей копии.

## Диагностика

- **Отказ UID map/newroot/old root:** проверьте реальный setup diagnostic и kernel AppArmor denial, соответствие helper/policy. Смена режима разрешений не исправляет изоляцию.
- **Helper отличается от системного binary:** нужен административный refresh; небезопасного fallback нет.
- **Runtime executable заменён:** закончите сборку и перезапустите этот экземпляр, не чужую активную сессию.
- **Connection refused/server offline:** проверьте логи и endpoint, явно загрузите корректную модель и продолжите сохранённую задачу.
- **Нет GGUF/projector/server:** исправьте активный путь в настройках; не загружайте/перезаписывайте файлы автоматически.
- **Ошибка памяти/vision:** проверьте контекст, KV, GPU layers и совместимость projector. Восстановление после полного исчерпания памяти не гарантируется.
