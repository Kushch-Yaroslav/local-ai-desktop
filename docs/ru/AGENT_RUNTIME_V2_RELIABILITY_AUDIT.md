# Agent Runtime V2: аудит надёжности

Дата проверки: 2026-10-21. Область изменений — Rust agent loop, durable transcript и Verification Gate. Пользовательский `runtime/`, проекты, модели и чаты не изменялись.

## Подтверждённые проблемы

| Приоритет | Причина | Последствие | Исправление |
|---|---|---|---|
| P1 | Защита от одинакового неудачного tool call хранила streak только в `AgentState`, создаваемом заново для каждого `run()`. Durable transcript сохранял вызовы и результаты, но guard при Resume начинал с нуля. | После Pause/Resume модель могла повторять ту же заведомо неудачную операцию и тратить ещё один tool call и цикл генерации. | Streak вычисляется по вызовам и результатам текущего пользовательского запроса в transcript. Успех, изменённые аргументы и новый запрос начинают новый retry window. Восстановленные при compaction результаты не учитываются как новые попытки. Существующее ограничение числа повторов и правила безопасности сохранены. |
| P1 | Verification Gate определял наличие правок по локальным `mutations`/WorkBudget текущего процесса. При Resume эти счётчики сбрасывались, хотя Task Memory уже сохранял изменения verification ledger. | Run мог завершиться без проверки ранее внесённых изменений, несмотря на сохранённый Task Memory. | Gate также учитывает persisted verification changes и неизвестную эпоху. Простые задачи без изменений и без нужды в проверке не получают обязательный план или дополнительный gate. |

Обе причины подтверждены по границам состояния: runtime state реконструируется на новый run, transcript и Task Memory переживают его. Добавлены regression tests, которые реконструируют durable transcript/состояние, а не проверяют только локальную функцию на одном объекте.

## Что изменилось

- Повторная идентичная неудачная операция после Resume распознаётся по durable истории. Новые аргументы или новый запрос не блокируются старым streak; успешный результат сбрасывает streak.
- Gate проверки изменений после Resume использует persisted verification ledger, а не только счётчики текущего процесса.
- Не добавлялись новые подсистемы, tool restrictions, автоматическое исполнение текстовых псевдо-вызовов или изменения Agent Security.

## Измерение эффективности

Scripted регрессия воспроизводит две неудачи одной операции, закрытие и повторное открытие transcript, а затем проверяет, что третий идентичный запуск будет остановлен существующим guard; изменённые аргументы, успех и новый запрос не блокируются. Это доказывает предотвращение повторного tool execution в данном случае, но не является измерением токенов или реального времени LLM. Реальный Qwen/GPT inference и benchmark не запускались.

Изменения Gate проверены на восстановленном Task Memory при нулевом локальном mutation counter. Это тест корректности Verification Gate, не оценка числа токенов.

## Проверки

- `cargo test --lib`: 295 passed.
- `cargo test --test agent_loop live_loop_pause_resume_correction_and_cancel_preserve_state -- --exact`: passed.
- `cargo test --test agent_loop runtime_pause_snapshot_survives_compaction_and_repeated_resume_without_replaying_edits -- --exact`: passed.
- Регрессия лимита идентичных tool calls: passed в Rust unit suite.
- TypeScript typecheck: passed.
- ESLint: passed.
- `npm run build`: passed (Rust agent, Vite renderer и Electron TypeScript сборка). Vite сообщает существующее предупреждение о крупных чанках; сборка завершается успешно.

Integration тесты используют scripted provider и локальный тестовый HTTP endpoint; они не являются тестами с реальной LLM. Без расширенного sandbox-разрешения локальный bind был запрещён; повторный запуск с разрешённым тестовым endpoint прошёл.

## Границы аудита

Аудит и исправления здесь целевые: они закрывают два воспроизводимых сбоя при восстановлении состояния. Не запускались тяжёлые GGUF, Electron UI E2E, полный набор integration/security/browser tests или замеры реального числа токенов. Другие потенциальные улучшения Agent Runtime не объявляются проверенными или исправленными этим отчётом.
