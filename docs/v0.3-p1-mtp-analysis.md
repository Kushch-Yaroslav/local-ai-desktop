## Switching and costs

MTP weights are conditionally loaded (`load_mtp`), and a second inference context is initialized against the target model. The server's launch-time configuration owns these lifetimes. Safe P1 switching therefore restarts only the owned server, reconstructing target and MTP contexts and clearing server KV-cache. Electron, chat history, Rust evidence/checkpoints and preview remain independent. Existing launcher ownership checks, bounded startup, rollback, GPU release waiting, CPU/GPU placement and context validation must remain in force.

Auto needs independent model-tensor and executable-capability checks. On must fail explicitly if either is unavailable. Off must explicitly select `--spec-type none`, regardless of any inherited speculative environment. Startup log confirmation and real accepted/drafted counters are needed before claiming actual MTP activity. A failed Auto launch should not loop; record one failure and leave safe Off recovery available.

Additional GPU/RAM cost is model/head/context dependent: MTP head weights, draft KV/compute buffers and saved target hidden states. Existing allocation-log parsing already separates speculative weights/KV/compute. No fixed memory delta is established before real measurement. Qwen3.6's existing four CPU MoE layers and batch placement must be retained; dense Qwen3.8 is the simpler primary performance fixture. Tests will use the same GGUF, context, placement, sampling, prompt and token ceiling across modes.

Streaming, reasoning and tool calls share the server's normal serialization after token verification; compatibility must be tested with actual inference. Hybrid recurrent model rollback and acceptance can affect performance. CUDA is the primary available tested backend; source-level support is not a claim that every GPU/CPU backend is certified. Metrics endpoint exposes actual speculative draft/accepted totals separately from generation throughput.

## Experimental early reasoning changes

There is no established safe API for changing effort inside an active SSE request. P0's native Pause/checkpoint followed by explicit task Resume can restart inference with requested settings while retaining completed observations. It deliberately discards unfinished reasoning/tool-call generation and may change continuation/token sequences. Automatic interrupt-on-selection is inappropriate. A separate confirmed action can reuse the existing Pause and logical-task continuation only if its full UI/IPC/history ordering and real Qwen behavior are verified; otherwise retain P0 next-request behavior.

## Conclusion

Embedded MTP is technically available with the current server and both local Qwen files; no backend rewrite or downloads are needed. Implement capability detection, persisted Auto/On/Off, an explicit guarded reload transaction and real metrics/benchmarks. Start with Qwen3.8-27B. Do not certify external MTP weights or token equivalence merely from metadata/CLI flags.
